00 / GETTING STARTED

Build faster from your terminal.

WROSECODE is a Rust terminal coding agent with a responsive TUI, tool execution, AI provider integration, saved sessions, headless automation and an authorized CTF workflow. You can install a packaged native binary or build the CLI from source.

Before you begin

The website is a frontend demo; installing WROSECODE gives you the separate terminal agent. Its actual model behavior depends on your installed version and provider setup.

01 / INSTALLATION

Install WROSECODE CLI.

Option A — npm: The easiest global installation method if the wrosecode package is published and its native release assets can be downloaded. Install Node.js 18+ first.

● TERMINAL / BASH
node --version
npm --version
npm install -g wrosecode
wrosecode --version
wrosecode --help

Or run once using npx wrosecode. To upgrade or remove the CLI:

● TERMINAL / BASH
npm install -g wrosecode@latest
# To uninstall:
npm uninstall -g wrosecode
Package availability

The npm installation command is from the project CLI guide; current public npm package availability was not confirmed. If npm reports 404 or no matching package, use the native assets below or a source build. The CLI package relies on working published native binary assets.

Use the download selector on the homepage for a platform-specific installation command, or choose a release binary below. Always verify checksum files from the release.

Linux example (x86_64)

● TERMINAL / BASH
curl -fL https://github.com/whiterose717/WROSECODE-CLI/releases/download/v1.0.0/wrosecode-linux-x86_64 -o wrosecode-linux-x86_64
curl -fL https://github.com/whiterose717/WROSECODE-CLI/releases/download/v1.0.0/wrosecode-linux-x86_64.sha256 -o wrosecode-linux-x86_64.sha256

wrosecode --version

macOS example (Apple Silicon)

● TERMINAL / BASH
curl -fL https://github.com/whiterose717/WROSECODE-CLI/releases/download/v1.0.0/wrosecode-darwin-aarch64 -o wrosecode-darwin-aarch64

shasum -a 256 wrosecode-darwin-aarch64
# Compare the hash with the official .sha256 file
chmod +x wrosecode-darwin-aarch64
./wrosecode-darwin-aarch64 --version

Windows (PowerShell)

Download wrosecode-windows-x86_64.exe (for most Windows PCs), verify the SHA-256 hash, then rename it to wrosecode.exe. The example assumes the file is in Downloads.

● TERMINAL / POWERSHELL
$file = "$HOME\Downloads\wrosecode-windows-x86_64.exe"
Get-FileHash $file -Algorithm SHA256
# Compare hash with the official release checksum
New-Item -ItemType Directory -Force -Path "$HOME\bin" | Out-Null
Copy-Item $file "$HOME\bin\wrosecode.exe"
& "$HOME\bin\wrosecode.exe" --version
Windows PATH

For command access from any directory, add %USERPROFILE%\bin to your user PATH through Windows Environment Variables. Open a new terminal after changing PATH.

03 / SOURCE

Build and install from Rust source.

For Kali Linux, Debian or Ubuntu, install build prerequisites and Rust, then clone the repository (requires access to the source).

● TERMINAL / BASH
sudo apt update
sudo apt install -y git curl build-essential pkg-config libssl-dev
# Install Rust via the official rustup script after reviewing it:
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
git clone https://github.com/whiterose717/WROSECODE-CLI.git
cd WROSECODE-CLI
cargo install --path .
wrosecode --version

Alternatively, use cargo build --release to create target/release/wrosecode. This method does not require npm.

Repository visibility

The GitHub repository root could not be independently fetched at verification time. If cloning returns 404, check whether the repository is public or authenticate as an approved collaborator.

04 / MODEL CONFIGURATION

Connect your AI provider.

The terminal agent needs a configured AI model to perform model-driven tasks. Use its provider manager to add a provider, save the key and verify the connection.

● TERMINAL / BASH
wrosecode providers list
wrosecode providers add
wrosecode providers set-key
wrosecode providers test

For a compatible local endpoint (such as a local OpenAI-compatible server):

● TERMINAL / BASH
export WROSECODE_OPENAI_URL="http://127.0.0.1:11434/v1"
wrosecode --provider openai-compat --model MODEL_NAME
Credentials

Never paste real API keys into public website forms or screenshots. Keep them in private local environment variables or the CLI provider manager. Check provider terms and billing before running automated tasks.

06 / AGENT CONTROL

Choose permissions & thinking.

Pick a permission policy based on your trust in the workspace. For ordinary development, auto-safe allows less risky operations automatically and prompts for sensitive actions.

● TERMINAL / BASH
wrosecode --permission ask
wrosecode --permission auto-safe
# CAUTION: skips prompts; disposable VM / trusted repo only
wrosecode --permission yolo

Thinking level

Choose from off, low, medium, high, max, and auto. The supported model and provider determine available performance.

● TERMINAL / BASH
wrosecode --think auto
wrosecode --think high
# Inside the TUI use: /think high
Use high-risk modes carefully

The yolo permission mode skips approvals but does not make untrusted binaries, scripts, or networks safe. Prefer sandboxing and explicit challenge scope.

06 / CHALLENGE MODE

Use the /ctf agent.

Start CTF investigations in the terminal against authorized challenge artifacts or challenge endpoints. The agent can use its configured tools and provider; actual solve performance is not measured by this website.

● TERMINAL / BASH
wrosecode ctf ./challenge-files/
wrosecode ctf ./capture.pcapng --category forensics
wrosecode ctf ./challenge --category crypto
wrosecode ctf ./binary --category pwn

Configure budgets and independent workers:

● TERMINAL / BASH
wrosecode ctf ./challenge --budget "steps=50,tokens=100000,seconds=1800" --parallel 4

Inside interactive mode:

● TERMINAL / TUI COMMANDS
/ctf ./challenge-files/
/writeup

For a remote target, supply only a host and port explicitly authorized in your challenge:

● TERMINAL / BASH
wrosecode ctf ./binary --category pwn --remote challenge.example:31337
Flags and verification

A flag-looking string is not independent proof of a solved challenge. Use the real challenge platform or authorized verifier when available. The website lab never claims it solved a challenge.

08 / PLATFORM INTEGRATION

CTFd commands & submission.

For competitions using an authorized CTFd instance, use the CLI's CTFd commands to inspect challenges, check the scoreboard and verify or submit flags as permitted.

● TERMINAL / BASH
wrosecode ctfd list
wrosecode ctfd scoreboard
wrosecode ctfd download
wrosecode ctfd submit
wrosecode ctfd verify

Configure credentials privately in your local shell:

● TERMINAL / BASH
export CTFD_URL="https://ctf.example"
export CTFD_TOKEN="your-private-token"
Submission caution

Some CTF competitions penalize wrong submissions. Only enable automatic submission after confirming the contest rules and your challenge authorization.

09 / ADVANCED

Sessions, automation and more.

Resume & fork existing sessions

● TERMINAL / BASH
wrosecode --session SESSION_ID
wrosecode --session SESSION_ID --fork
wrosecode --session SESSION_ID --export-session session.json

Automatic test repairs

● TERMINAL / BASH
wrosecode --check-command "cargo test" --repair-retries 5 "fix the tests"

Structured automation & events

● TERMINAL / BASH
wrosecode exec --json "analyze the repository"
wrosecode --events events.ndjson --headless "run the tests"
wrosecode --trace "investigate slow tests"

Dashboard and local server

● TERMINAL / BASH
wrosecode dashboard
wrosecode --listen 127.0.0.1:7878
Keep the agent local

Do not expose a shell-capable WROSECODE listener to the public internet without strong authentication, authorization, origin controls and isolation. The hosted website contains no agent server.

10 / SUPPORT

Fix common setup problems.

"wrosecode: command not found"

Verify that installation completed and the global executable folder is in PATH. Open a new terminal after updating your shell environment.

● TERMINAL / BASH
npm prefix -g
export PATH="$(npm prefix -g)/bin:$PATH"
wrosecode --version

npm reports 404 or installer cannot fetch a release

Confirm the npm package is published and the GitHub release assets are accessible. Install a native binary or compile from source when you have repo access.

CHECK GITHUB RELEASES ↗

Model authentication fails

Re-enter your provider credential, confirm model access and test it directly.

● TERMINAL / BASH
wrosecode providers list
wrosecode providers set-key
wrosecode providers test

Need exact commands for your build?

Use the help output provided by the installed binary; commands and options may change after v1.0.0.

● TERMINAL / BASH
wrosecode --help
wrosecode providers --help
wrosecode ctfd --help
